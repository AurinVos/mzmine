Removed Colt and JCIP

The CERN portion is permissive, but bundled hep.aida.* forbids military use.
There are no cern/ or hep/aida/ bytecode references across all 278 installed
runtime jars excluding Colt (build/license-audit/colt-bytecode-reference-scan.txt).
Exact gs-algo2.0 sources also contain no Colt references. No active MZmine
Java sources reference cern.*, hep.aida.*, or net.jcip annotations.
net.jcip:jcip-annotations:1.0 declares Creative Commons Attribution without
specifying the version. Removing this unused runtime artifact avoids inventing
a precise grant. Do not exclude either artifact merely from license reporting.

org.jdom:jdom2:2.0.4
The exact binary jar's LICENSE.txt and the POM license comment contain the
custom JDOM grant, with preservation, non-endorsement and name restrictions,
and an OPTIONAL acknowledgement. It is not Apache License 1.1 and should
not be mapped to that GPL-incompatible license. The actual notice is preserved
in licenses/third-party/JDOM-2.0.4-LICENSE.txt. The GPLv3 distribution retains
these trademark/name restrictions in accordance with GPLv3 section 7(e).
Primary explanation: https://www.jdom.org/docs/faq.html

Removed Adobe XMP and JJobs source-unavailable runtime artifacts
No de/unijena/bioinf/jjobs/ references exist across the 276 installed jars
excluding JJobs/XMP. JJobs is not needed by the application's SIRIUS API calls.
The only Adobe XMP reference is jasperreports-pdf7.0.3 XmpWriter, isolated behind
PdfXmpCreator.supported(). Exact Jasper sources show Class.forName probing with
ClassNotFoundException fallback, and ClassicPdfWriter.createXmpMetadata() uses
OpenPDF metadata generation if Adobe is absent. Ordinary PDF exports are unaffected;
custom PDF/A configurations fall back to OpenPDF and must not claim separately
verified Adobe XMP metadata conformance.
Older Adobe6.1.10/5.1.3 source jars and drewnoakes source fork contain a restrictive
ADOBE CONFIDENTIAL notice, so they are not used as replacement source evidence.
